Project Overview
Build a Snowflake data warehouse to analyze stock market data ingested from Kafka topics (both batch and streaming data). Raw data is stored in S3, transformed via PySpark, and loaded into Snowflake. Airflow orchestrates the entire pipeline.

1. Data Extraction
Source:

Both batch (end-of-day) and streaming tick data are ingested through Kafka topics.

Kafka producers push data from Yahoo Finance (batch) and Alpha Vantage (streaming).

Raw Data Storage:

Kafka consumer jobs write raw CSV files to designated S3 raw zones (separate folders for batch and streaming data).

Frequency:

Batch data: Once daily, pushed to Kafka, then to S3.

Streaming data: Continuous near real-time, pushed to Kafka, then to S3.

Orchestration:

Airflow DAGs monitor Kafka consumer jobs and S3 raw data availability.

2. Data Transformation
Batch Transform (PySpark):

Read raw batch CSV files from S3 raw zone.

Clean, deduplicate, apply business logic (KPIs, dimensions).

Load transformed data directly into Snowflake.

Airflow triggers batch transformation after raw data arrival.

Streaming Transform (PySpark Structured Streaming):

Read raw streaming CSV files from S3 raw zone.

Clean, deduplicate, watermark late events.

Enrich with dimension data, aggregate metrics, detect anomalies.

Write transformed output files back to S3 transformed zone.

Airflow monitors streaming transformation job health.

3. Data Loading
Batch:

Load dimension and fact tables into Snowflake using bulk COPY or connectors from batch transform output.

Streaming:

Snowflake Snowpipe watches transformed S3 zone and automatically ingests streaming data into Snowflake.

Orchestration:

Airflow tracks load completion, triggers alerts on failures/delays.

4. Monitoring & Quality
Data quality checks integrated in transform jobs.

Centralized monitoring and alerting via Airflow.
